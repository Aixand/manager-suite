# Aixand launch context, version 1

Applications use this contract when launching work through Agent Manager or
directly through Undercurrent. Labels are query-visible strings; metadata is
durable detail available through explicit reads. Undercurrent remains the
authority for runtime identity, lifecycle, health, and observations.

## Common labels

| Key | Meaning |
| --- | --- |
| `app` | Application responsible for this work, such as `editor` or `example-app`. |
| `origin.app` | Original initiating application, retained across application handoffs. |
| `feature` | Application-specific activity, such as `planning`, `workflow`, `chat`, or `app-server`. |
| `session.kind` | Process category: `server`, `agent`, `shell`, or `job`. |
| `service.name` | Required for a `server`, such as `codex-app-server` or `runner`. |
| `project.id`, `project.name` | Shared project identity and readable name, when applicable. |
| `workflow.run_id`, `workflow.step_id`, `workflow.name` | Workflow association, when applicable. |
| `role` | Agent responsibility, such as `planner`, `fixer`, `implementer`, or `reviewer`. |
| `agent_manager.run_id`, `agent_manager.profile` | Reserved identifiers generated by Agent Manager. |

Product extensions use their namespace: `pathspec.*` and `suite.*`. Additional
keys may be present. Process category describes purpose:
an agent accessed through a terminal is still an `agent`.

## Construction and inheritance

`application_context(app, feature, inherited=..., project=...)` preserves
inherited labels and metadata while assigning the supplied application and
feature. An existing `origin.app` remains the original origin. Explicit caller
labels cannot replace the application/feature supplied to this helper.

Pass `session_kind` for a direct process launch; server launches also require
`service_name`. This replaces inherited process classification. Agent Manager
automatically classifies native terminal agent launches as `agent`.

Derived process attributes are applied after keyed-launch recovery, so adding
new defaults does not change previously accepted launch identities. Reusing
an existing server does not relabel it to the latest requesting application.
Shared servers receive app-level context separately from individual threads.

Logical threads have task context without `session.kind` or `service.name`.
Terminal attachments restore their thread's task context, classify their own
process as `agent`, and record `session.thread_id` in private metadata when applicable.

Use the same explicit `project.id` across applications and machines. Otherwise,
`project_context` derives an ID from the canonical original project root.
Working copies use that original identity; changing the original root does not
inherit another project's ID. `project.root` is private metadata.

## Names and metadata

New managed native agent sessions use `<profile>-<adjective>-<noun>`, such
as `work-calm-otter`. Words are selected locally from 256 adjectives and 512 nouns.
Names are reserved under the manager registry lock and remain reserved after
finalization. Workers check the target daemon before submission and reroll on a
collision. A creation race is retried only when the daemon explicitly reports a
name conflict with no launch effect; uncertain submissions retain their saved
name for recovery. Very long profile prefixes are shortened to fit the runtime's
128-character name limit. Full run IDs, session IDs and recovery labels remain
separate from these readable names.


Metadata contains bounded references, paths, provenance, digests, and process
relationships. Keep full artifacts in their existing durable application files.
Both maps accept 64 entries; keys are at most 64 UTF-8 bytes, label values 256
bytes, and metadata values 4096 bytes. Structured metadata uses JSON strings.

Application-specific metadata belongs to the embedding application; Agent Manager
does not implement Suite group restoration or Runner integration.

## Existing sessions

This contract applies to future launches. Existing runs, threads, pending
launches, and session names remain unchanged. The current Undercurrent CLI and
product API do not offer in-place updates to session label/metadata maps.
Do not restart work or edit the daemon database to backfill this contract.
